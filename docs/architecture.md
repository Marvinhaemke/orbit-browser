# Native Firefox integration

## Source and build

`firefox-source.json` pins Mozilla’s `mozilla-firefox/firefox` Git repository to revision `3f73c528a1ae5784ea5e1ee2c5ad3762507395f2`. The first artifact build targets that same revision, rather than silently mixing an arbitrary engine with the UI source.

`overlay/` mirrors Firefox source paths. Preparation verifies Git blob hashes for the upstream files it needs to modify, installs the overlay, registers the new component, packages its UI assets into Firefox’s browser chrome, and applies Orbit’s prototype branding. An upstream upgrade is a deliberate change to the pin and hook expectations.

The Windows pipeline bootstraps the supported Mozilla toolchain, rebuilds the frontend, packages the browser, then launches that browser with a disposable profile for a native runtime smoke test. It must pass before the downloadable artifact is uploaded. For updater or test changes with unchanged native source, configuration, build environment, and build command, it can reuse a retained native build from this repository's `main` branch. The internal build cache is recorded after packaging and may be untested; source, workflow, run provenance, and every file hash are verified before reuse. All fresh-browser and updated-installation checks still run before public uploads or release publication. Changes to native hooks, modules, markup, branding, registration, the engine pin, configuration, or native build scripts require a new build. Four registered, unprocessed Orbit CSS resources can be repackaged in a matching native build: each original archive entry must match its trusted baseline Git blob hash before any archive is changed, allowing only Windows checkout CRLF normalization. Every other archive entry and all engine/profile files are preserved. The resulting browser runs the same complete fresh and updated runtime checks before publication. An expired or unavailable prior artifact also causes a new build.

## Prototype interface updates

`scripts/package_update.py` packages only `omni.ja` and `browser/omni.ja` from a verified native build. Its manifest records the source commit, exact upstream pin, payload hashes, and hashes of the unchanged native executables and DLLs. The application executable, engine, and profile are omitted from the update. Both `application.ini` and `platform.ini` stay with the installed application; their per-build identifiers are not used as engine fingerprints. The two NSIS utilities rebuilt during frontend packaging, `uninstall/helper.exe` and the root `maintenanceservice_installer.exe`, also stay untouched and are excluded from the engine fingerprint. Neither loads the interface or renders webpages. The actual `maintenanceservice.exe` and every other executable and DLL retain strict fingerprints. Older updater scripts must be refreshed once to recognize the additional packaging utility.

The Windows PowerShell updater fetches the fixed repository’s `windows-prototype` release assets. It validates the installed engine and staged files before replacing either archive, rejects unexpected ZIP paths, requires Orbit to be closed, and restores the previous archives on an installation failure. It saves the initial interface in `.orbit-update-backup`, records the installed UI commit, and adds `browser/.purgecaches`. Restarting with `-purgecaches` invalidates compiled interface caches while keeping the existing profile. An unchanged interface skips downloading the payload.

CI tests the Windows updater, applies the bundle to a copy of the actual native package with different existing archives, checks profile preservation, and runs the native browser smoke test again. A separate job with release-write permission publishes the rolling release only after all Windows checks pass. The manifest is uploaded after its payload; any mismatched assets during publication fail hash validation. Pull requests never publish the update channel. This prototype channel handles interface changes on a compatible engine; a Gecko upgrade requires a full browser package.

`installer/orbit.nsi` wraps the same tested package in `Orbit-Setup.exe`, a per-user NSIS installer that needs no elevation. It installs to `%LOCALAPPDATA%\Programs\Orbit`, keeps the profile in the installation's `profile` folder, and puts its uninstaller and shortcut icon in `.orbit-install`, which the updater excludes from the engine fingerprint. Setup only writes to a new or empty folder or an existing Orbit installation, refuses while that installation's `orbit.exe` is running, replaces every program file except the profile, and adds `browser/.purgecaches`. Shortcuts, the finish page, and the updater's relaunch all pass `-profile`. `orbit.exe` is Mozilla's prebuilt executable, whose compiled application data still names Firefox (the packaged root `application.ini` is not read), so a start without `-profile` selects a profile from `%APPDATA%\Mozilla\Firefox\profiles.ini`. Setup never edits that list, so a taskbar pin made from the running window opens a separate profile; pinning the Start menu shortcut keeps `-profile`. The uninstaller keeps the profile unless the person chooses to delete it. CI installs the package silently, compares every installed file, checks shortcuts and registration, starts the installed browser with its profile, confirms that Setup refuses while it runs, applies the interface update to the installed copy, reinstalls, runs the native smoke test, and uninstalls. The publish job then uploads `Orbit-Setup.exe` and `Orbit-Windows-x64-portable.zip` with checksums to the same release, moves its tag to the verified commit, marks it as the latest release, and compares the public downloads with the tested files.

## Runtime

`browser/components/orbit/Orbit.sys.mjs` is a privileged browser component loaded during Firefox’s delayed window startup. It manages the toolbar entry, keyboard shortcut, canvas lifecycle, and a narrow bridge to native browser operations. Firefox’s `AboutNewTab.newTabURL` routes native new-tab commands to the packaged canvas while preserving its initial-page address-bar behavior. Orbit sets it from the `browser-before-ui-startup` category, before the first window opens, and the branding prefs ship the canvas as the default `browser.startup.homepage` (people can still change it) with Firefox's onboarding tab disabled. A canvas that loads as a window's home page can connect before that window's delayed startup; it receives only its document-bound bridge, and toolbar, theme, radial, and focus integration still wait for `Orbit.init` at delayed startup. The canvas viewport fills the page beneath floating sidebar and top-bar panels; camera coordinates are measured from the free area beside and below them.

`browser/base/content/orbit/orbit.html`, `orbit.css`, and `orbit.js` form the spatial canvas. They are packaged as `chrome://browser/content/orbit/` resources. The canvas lives inside Firefox’s own chrome; it is not an extension page or a standalone website.

The canvas bridge manages real `gBrowser` tabs and uses the current native split-view support. Peek renders a real Gecko content browser. Browser navigation keeps Firefox’s process isolation, normal URL handling, and container context. Saved cards retain URLs for tabs that have been closed, so frames can be reopened.

The canvas's open-tabs tray and the radial **Send to canvas** frame fans share one placement path in `Orbit.sys.mjs`. `placeTabs` accepts up to 100 live web-tab ids and an optional validated frame id or finite canvas point. A tab reuses its own card, or a saved card with the same address and container that no live tab owns; it never gets a second one. Placement into a frame takes the first free slot, skips slots that a smaller nested frame claims, and grows the frame when it is full. A dropped point centers the card there, and frame membership follows the card's center. The calling canvas is not sent its own `board-changed` echo, so it keeps an undo step for the placement. `closeTabs` closes up to 100 tabs and opens a new tab first if no other tab would remain. While the overlay canvas is visible it closes them without the closing animation and keeps the overlay open through the resulting `TabSelect`. Cards are never removed with their tabs. The tray's drag data is a random per-drag token, and the tab ids stay in the page, so a drop into a webpage learns nothing. For radial captures, the parent recomputes the frame targets from the saved board and looks up the activated item by id, so a frame id supplied by the menu is never trusted. `listTabs` reports a tab's favicon only as a local raster `data:` URL of at most 16 KB.

The canvas's address field never navigates by itself: the bridge's `focusAddress` hands its text to `gURLBar.search` (or `select`), and Firefox's address bar owns search, suggestions, URL fixup, and Enter. Shortcuts come from `NewTabUtils.activityStreamLinks.getTopSites`, the same frecency query and block list as Firefox's regular New Tab. The bridge passes on only HTTP/HTTPS addresses, plain-text titles, and local raster `data:` favicons; private windows and the `browser.orbit.newtab.shortcuts` opt-out never query history. A shortcut loads in its own native canvas tab with a fresh null principal and that tab's container. Removing a shortcut adds it to Firefox's top-site block list.

Workspace data is stored through Firefox SessionStore custom window values. Tab identities use custom tab values. Private windows keep a separate in-memory workspace. Layout restoration follows session restoration, rather than a cloud account or browser localStorage.

Each native canvas tab receives an immutable bridge bound to its current system-principal document and native browser. Navigation, tab closure, BFCache/discard, and foreign browser ownership revoke privileged access. Toolbar overlays retain their separate exact-document guard. An overlay canvas stays in front while the person uses Firefox's address bar, whether from its search field or Ctrl+L. Escape there belongs to the address bar, and focus Firefox returns to the page beneath moves to the visible canvas. The overlay steps aside when the address bar announces a navigation (`urlbar-user-start-navigation`), so the opened page is visible. Shared workspace changes notify live canvases without echoing the author’s save.

`OrbitTheme.sys.mjs` installs scoped browser chrome styles. It follows Firefox’s effective theme identity, leaving custom theme colors intact. Native default chrome, radial menus, and the canvas use Orbit’s liquid/sculpted palette with reduced-motion and forced-color support. The branding overlay supplies Orbit’s SVG logo, vector wordmarks, and About styling.

The browser component controls the boundary between the canvas and website content. Website titles and URLs are untrusted text. Canvas actions accept website URLs and explicit native tab identifiers; they must not expose arbitrary evaluation or unrestricted privileged navigation.

`OrbitRadial.sys.mjs` owns a radial-menu controller for each browser window. Trusted pointer events arrive through `OrbitRadialChild` and `OrbitRadialParent` JSWindowActors; the parent validates that their current browsing context belongs to the selected native tab. Held tab wheels stay pointer-transparent so the original webpage receives button release and Firefox can construct the correct link, image, selection, or editing context, including cross-origin frames.

The page wheel snapshots Firefox's initialized `contentAreaContextMenu` and invokes its original commands. It retains the native context descriptor for those commands, suppresses the ordinary popup, and completes its cleanup when the wheel closes. The tab wheel reads native open tabs and tab groups, including internal pages and collapsed groups. `OrbitRadialView.sys.mjs` renders circular sculpted controls over a decorative disc and locally anchored submenu fans. Backing surfaces never receive pointer input; hit tests match the circular command targets. Overflow is paginated recursively. The view handles hover, keyboard input, animation, viewport bounds, and reduced motion. Commands get stroke glyphs chosen from their native or Orbit identifier; tabs without a local favicon get a site monogram. The native snapshot carries Firefox's localized single-character access keys. A unique key activates its command (or opens its fan), a shared key cycles, and other letters highlight the next matching label. Keys of commands paged behind More open that page first. Key badges, the hub's direction arc, and the caption's detail line are decorative and never receive pointer input. Website text is rendered as text, and content messages cannot supply privileged commands or menu definitions.

`OrbitInteractions.sys.mjs` manages a native command bar and reversible focus mode for each browser window. New ordinary windows enter focus mode during delayed startup unless `browser.orbit.focus.default` is `false`; windows whose chrome Firefox hides, fullscreen windows, and customization keep their native layout. Firefox focuses a blank window's or new tab's address field before delayed startup, so the default keeps that focus and shows the expanded address island instead of moving focus to the page. Command results refer to live native tabs or validated workspace frame identifiers; they do not execute typed text. The command bar uses ordinary DOM text, restores focus on dismissal, and supports keyboard navigation. Focus mode presents the original address bar and window buttons as independently revealed floating islands. It keeps their native nodes, event handlers, and popup ownership; exiting restores their ordinary layout. Small hover regions use dwell and dismissal delays, and keyboard focus keeps the corresponding island visible. Focus mode changes browser chrome presentation without requesting webpage fullscreen or changing browser preferences. To find which toolbar owns the native window buttons, the islands' layout code briefly restores the native toolbar and measures it, with island transitions off so nothing animates from the native positions. It re-measures, at most once per frame, only when an attribute Firefox's titlebar-button rules depend on changes (`customtitlebar`, `inFullscreen`, `sizemode`, the menu bar's `autohide`/`inactive`/`collapsed`, the toolbox's `tabs-hidden`) or the vertical-tabs preference changes. It never re-measures on class changes, which layout itself produces, for example in open address suggestions.

`OrbitFocusTools.sys.mjs` uses the shared radial renderer for the top-left tools menu. Its `corner` layout pins the hub to the window corner (a quarter-circle New tab button), places root commands on one or two arcs inside the quarter, and fans submenus beyond them, clamped so every circle stays on screen. Only a small corner hotzone opens it; there is no permanent trigger button. Browser commands retain Firefox's native controllers; extension actions retain the original BrowserAction implementation, including selected-tab state and private-window eligibility. Each radial view has its own element and gradient identifiers, so a tools menu can coexist safely with a dismissing page wheel.

If a user has added Firefox's separate search widget, its native search shortcut temporarily reveals the original toolbar while that widget or its popup is in use. Leaving it restores the floating controls without changing the user's customization.

The radial menu's capture commands use Firefox's existing context descriptor. `Orbit.sys.mjs` validates HTTP/HTTPS addresses and containers before storing a page or link card, or a selected-text note with a plaintext source annotation. Captures use the same window-scoped persistence and private-memory rules as canvas edits.

`scripts/smoke_radial.py` exercises physical right-button down/up gestures against the packaged native browser, checks real command effects and group expansion, and captures light and dark screenshots. CI repeats these checks after applying the interface update to an existing installation.

`scripts/smoke_ux.py` exercises the command bar, focus controls, and webpage capture with trusted native keyboard and pointer input. These checks also run against an updated existing installation before publication.

## What remains upstream

Gecko rendering, the native tab strip, extensions, downloads, settings, permissions, developer tools, and the operating-system integrations come from Firefox. This prototype concentrates changes in browser chrome and packaging. Their continued behavior needs platform regression testing as the fork grows.

Desktop platform support should share one runtime implementation. Windows, Linux, and macOS each need their own build, launch, package, and verification steps.
